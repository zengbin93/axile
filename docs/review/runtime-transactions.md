# 数据库事务与账户 worker 的边界

SQLite 允许多个进程访问同一个文件，但同一时刻只能有一个写者。主进程不能持有事务等待需要写库的 worker；WAL 和 busy timeout 无法解除这种循环等待。

账户同步分成三段：短写事务登记尝试并读取独立配置快照；关闭会话后应用 scheduler / worker；新事务写尝试审计并按版本条件更新状态。先取得短写事务再读快照，避免 WAL 读事务升级时使用过期快照。成功、失败都必须检查 revision；旧版本只留下审计，随后继续对齐最新目标。

创建、修改和重试入口先提交配置，释放请求会话后按账户 ID 调用同步。资产刷新、目标刷新、自定义函数试跑和通知预览也在访问 worker 前关闭只读会话，返回后如需保存结果则使用新事务。SQLAlchemy 默认允许关闭后的会话重新使用；关闭会分离已经加载的对象，不能在调用阶段访问懒加载关系。

运行态对齐、账户删除和盘前准备使用同一账户异步锁。等锁时不持有事务；盘前准备取得锁后重新读库；删除在锁内提交后清理 worker。同一账户串行，其他账户可以并行。这依赖服务现有的单服务端进程部署约束，不替代交易执行互斥，也不承诺跨多个服务实例协调。

取消留下 pending 并传播取消，失败留下 failed；继续使用启动恢复和手动重试，不新增后台重试任务，不重放下单。WAL + 30 秒 busy timeout 处理正常短竞争，synchronous=FULL 保留已提交控制记录的掉电持久性。

回归测试使用真实文件库、显式读事务和独立子进程，覆盖 DELETE/WAL、旧版本成功或失败、更新与删除交错、取消重试及各路由调用边界。调仓和清仓的现有编排已在读取上下文的会话退出后调用后端，保留这一约束；新增 worker 入口也必须遵守。
