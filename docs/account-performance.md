# 账户收益与组合回测

账户「实盘绩效」使用执行记录中的资产、目标权重和首笔行情，比较账户累计收益与 WBT 组合回测收益。不会读取外部行情，也不会发起交易。

## 设置

- 模式默认为「时序」，可选「截面」，分别使用 WBT 原生 `ts`、`cs` 聚合。
- 单边费率默认为 0 BP，支持 0 / 5 / 15 / 30 BP 预设和自定义小数；1 BP = 0.0001，不改变实际执行费用。
- 「保存并计算」原子写入账户字段 `backtest_weight_type` 和 `backtest_fee_rate`，跨会话保留。
- 修改设置重新计算整个选定区间，不按历史设置变化切段。

## 计算口径

WBT 0.8.2 输入为 `dt / symbol / weight / price`。时间取执行记录时间，权重取 `raw_input.curr_target`，价格取 `raw_result.symbol_results[symbol].first_tick` 买卖一中间价。兼容旧版顶层 `first_ticks`；归一化目标快照仅用于同一执行 ID 的目标补缺。

权重保留符号，精度固定 8 位，不额外归一化。时序模式按引擎原生规则对品种收益求平均，截面模式求和。WBT 日内 BAR 收益求和，再对日收益复利累计；账户收益为总资产相对共同基准的比值。两条曲线不保证在零费率下重合。引擎首 BAR 不计收益和费用，不额外模拟初始建仓成本。

账户收益不调整出入金；收益差额为账户减组合，单位为百分点，不等同于执行损耗。执行前首笔行情与执行后资产也不是严格同步估值。

30/90 天以最新执行记录为截止，使用区间前最后一个可用共同基准；无前置基准则从区间内首个共同观测开始。按上海本地时间归日，基准点保留实际执行时间。

换绑标记取绑定历史，理论目标只在新执行出现时改变。清仓写入零权重退出行。必要行情缺失后组合累计收益及差额中断，不补零、不插值、不用未来行情恢复累计值；账户仍可独立展示。选择缺口之后的区间可建立新基准。

## 接口与迁移

`PATCH /api/v1/account/performance-settings/{account_id}`

```json
{"backtest_weight_type": "ts", "backtest_fee_rate": 0.0002}
```

两个字段必填；费率为有限数值且 `0 <= fee_rate < 1`。只提交数据库变更，不协调调度或重连渠道。

`GET /api/v1/account/performance/{account_id}?range=all`

范围可选 `30 / 90 / all`。响应包含实际设置、引擎版本、共同基准、覆盖数量、每日及累计收益、换绑标记和首个缺口。读取完整历史，不受列表分页上限影响。

可选查询参数 `include_backtest` 默认为 `true`，保持原有完整回测行为；响应中的 `backtest_included` 表示是否包含回测。使用 `include_backtest=false` 时跳过 WBT 输入构建与计算，直接返回同一范围、基准和日末口径的账户收益。此时所有组合收益和差额字段均为 `null`，`used_record_count=0`、`gap=null` 仅表示未计算回测，不代表完整覆盖或无缺口。

页面并行请求账户快速结果和完整回测，账户收益到达即可展示。完整结果就绪后整体替换时间轴与数据，不拼接不同读取时刻的结果；迟到的快速结果不覆盖完整结果。参数保存后只刷新完整回测，等待或失败时保留已有曲线与其实际计算参数，错误可独立重试。本次渐进加载改造不新增数据库迁移。

迁移 `0010` 为历史账户初始化时序、零费率。部署新代码前须执行项目既有数据库迁移流程；回滚会删除这两个配置字段，不删除执行历史。

## 验证样本

使用 Axon 账户 2 `dummy-binance-90d` 的数据库副本：2,160 条记录，6,480 个有效目标与盘口条目。原数据库只读。

| 全部区间 | 账户累计收益 | 组合回测累计收益 |

| 时序，0 BP | 20.669350% | 5.563932% |
| 时序，2 BP | 20.669350% | 5.549855% |
| 截面，0 BP | 20.669350% | 17.473265% |
| 截面，2 BP | 20.669350% | 17.426256% |

以上是 2026-06-09 18:00 至 2026-09-07 17:00 的假数据验收结果，不代表实盘业绩。
