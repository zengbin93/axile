# 自定义通知函数

账户执行通知与系统执行告警默认继续使用飞书 webhook。高级设置可改为一份 Python 函数；每个账户最多一份执行通知函数，整个系统最多一份系统执行通知函数。保存时直接覆盖当前源码。

函数必须是同步函数，入口固定为 `notify(context)`。函数自行发送消息，可以使用任意通知渠道；返回值被忽略。自定义模式不需要飞书 webhook。函数运行在独立进程中，最长 15 秒。函数失败只记录通知错误，不改变交易结果，也不会自动补发默认飞书卡片。

## 执行通知

```python
def notify(context: dict) -> None:
    if context["execution"]["is_test"]:
        return
    status = context["execution"]["status"]
    trades = context["summary"]["trade_count"]
    # 在这里调用自己的通知服务。
```

`context` 的主要字段：

| 字段 | 内容 |
|---|---|
| `event_id` | 与本次 execution 关联的通知事件标识 |
| `account` | 账户 ID、名称、市场、交易渠道等不含连接凭据的字段 |
| `execution` | execution ID、类型、触发来源、状态、结论、原因码与原因、成功与否、错误、耗时、通知时间、`is_test` |
| `strategy` | 已去除疑似凭据字段的算法和交易规则 |
| `assets` | 总资产、可用资金、持仓市值、币种、快照时间和来源 |
| `targets` | 本次目标、上次目标、目标数量 |
| `positions` | 当前持仓及目标数量、目标权重；资产不可用时为 `null` |
| `orders` / `trades` | 本次订单和成交 |
| `symbols` | 各品种状态、结论、原因码与原因、错误、目标数量及订单成交计数 |
| `summary` | 品种、订单、成交及成功失败品种的计数 |

函数获取的是执行结束时固定的脱敏快照。资产不可用时相关字段可能为 `null`，应按实际来源处理。

## 系统执行通知

```python
def notify(context: dict) -> None:
    if context["is_test"]:
        return
    error = context["error"]["message"]
    # 在这里调用自己的通知服务。
```

系统上下文包含 `event_id`、`event_type`（`execution_error` 或 `execution_timeout`）、`execution_id`、`occurred_at`、`account`、`error`（类型、消息、堆栈）与 `is_test`。

试跑会执行页面中的当前草稿，函数可能实际发送消息。样例事件的 `is_test` 为 `True`，可用于跳过真实发送。生产函数的外部服务凭据应由部署环境管理，不要写进通知正文或日志。
