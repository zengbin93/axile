# CTP 会话就绪与恢复验证（R01 / #41）

## 实现边界

一个 `CTPExecutor` 实例是一轮连接代次。任一交易或行情前置断线后，该实例永久失效；SDK 再次触发连接、登录或行情回调不会恢复其就绪状态。worker 下一次解析执行器时关闭旧实例，创建新实例；当前执行不在旧实例上自动续单。直接使用执行器的调用方也必须重建实例并注册新的回调和订阅。

新实例依次完成认证、交易登录、当前交易日结算确认、非空合约目录加载、同交易日行情登录，以及订单、成交、持仓、资金查询屏障，才返回会话就绪。新实例拥有独立 API、SPI、阶段事件、错误和缓存；认证、登录、结算响应关联请求编号，重复或不匹配的响应被忽略。

会话就绪与品种行情就绪分别检查：显式订阅目标品种，收到成功订阅回报以及该实例、该交易日的新行情后，才能向原生 API 发单。检查位于账户控制等待之后的实际发送点。订阅失败、行情恢复超时或交易日变化不能通过旧缓存放行。不依赖 SDK 自动重订阅。

对账查询必须收到结束帧且无错误。空持仓、订单或成交合法，资金或合约空结果阻断初始化。成交通过 `(ExchangeID, OrderSysID)` 关联查询到的原始订单会话；不能证明归属的成交阻断，禁止使用当前 SessionID 猜测旧订单归属。查询期间到达的启动成交回报合并、去重后才发布就绪状态。多次查询不承诺柜台侧的原子快照；这是当前交易日的恢复查询屏障，不是跨日历史总账证明。

## 离线验证

`tests/unit/executor/ctp/test_connection_recovery.py` 使用实际 `TraderSpi`、`MarketSpi`、执行器及 OpenCTP 请求对象，将 API 的传输端替换为可控制的请求/回调驱动。它不是柜台录制数据，不能替代真实网络恢复验证。

覆盖认证/登录未完成、阶段拒绝、超时、旧请求/重复回调、交易和行情前置断线、同日 SessionID 变化、交易日切换、worker 失效重建和正常复用。初始化期间逐请求检查会话仍未就绪；原生发送点检查断线和品种行情就绪；对账验证旧会话成交关联、启动回报先于订单查询到达、查询错误后的迟到成功、空必要数据和交易日不一致。

行情测试要求显式订阅、成功确认与新回报，覆盖订阅拒绝、缺少确认、行情超时和交易日变化。原有 worker 账户/配置复用及预期交易日测试保留。

本次验证环境：Python 3.12，OpenCTP `6.7.7.1`。

```bash
uv run ruff format --check axile tests
uv run ruff check axile tests
uv run ruff check axile/executor/ctp/ctp_execute.py --select C901
uv run basedpyright
uv run pytest tests/ --ignore=tests/live --cov=axile --cov-fail-under=69
```

结果：1,383 项测试通过，总覆盖率 79.39%；格式、lint、复杂度及类型检查通过。

## 必须保留的联调待验证项

- 行情端点恢复后取得全部目标品种的订阅确认和新行情，记录到达顺序。
- 在真实 SDK 连接上触发交易、行情断线，验证旧实例永久失效、新实例重建成功。
- 用包含旧会话订单/成交及非空持仓的柜台数据核对恢复结果；验证真实日切和同日 SessionID 变化。
- 记录柜台是否完整提供当前交易日历史，以及无法关联成交被阻断时的具体证据。

这些待验证项由 [#45](https://github.com/zengbin93/axile/issues/45) 跟踪，不因 R01 代码修复和离线测试通过而视为完成。自动重订阅不在本实现的依赖中；#36 的其他成交归属边界、#37 的价格有效性与持续行情时效性仍各自保留。
